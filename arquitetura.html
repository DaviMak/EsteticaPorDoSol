Pipeline de deploy

Da máquina local à revisão em produção — executado por deploy.bat, sem exigir .NET SDK nem Docker instalados.

ETAPA 1
Código-fonte
deploy.bat chama deploy.ps1, que valida pré-requisitos, provisiona o que faltar e envia o código.
→
ETAPA 2
Cloud Build
Compila no servidor: dotnet restore, publish e build da imagem a partir do Dockerfile.
→
ETAPA 3
Artifact Registry
Guarda a imagem versionada por timestamp — estetica:20260729-212200 — permitindo rollback.
→
ETAPA 4
Cloud Run
Cria uma revisão nova, aplica as migrations no boot e move 100% do tráfego ao ficar saudável.
Migrations aplicadas na inicialização

O container executa db.Database.Migrate() antes de escutar na porta, porque não há .NET SDK na máquina local para rodar dotnet ef database update. Uma lock table no banco impede que instâncias simultâneas corrompam o schema — mas uma migration com erro impede a aplicação de subir.
